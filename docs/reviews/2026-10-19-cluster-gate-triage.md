# 2026-10-19 · cluster_fidelity 门禁 triage：红根二分 + 口径勘误

> 由 Stage 34 打磨轮的复查触发（"门禁在本轮前已红"）。本轮**只查因**，不动语义；决策待拍板。

## 0. 结论（一屏）

1. **红根 = `d739304`（mini 整数语义发放）**：父提交 `31a9b94` PASS、子提交 FAIL，逐位复现；其后至现值（含 A/B 打磨轮）门禁数字**逐字不变**。
2. **性质 = 系统性台阶**（非种子抽签）：n=400 pop 相对偏差 **~1.8% → ~5.4%**，三个独立种子块全部翻转；t=4000 逐 trial sd≈9.5、SEM≈2.1 ⇒ 步进 ≈ 7×SEM。
3. **消融定位到单个算子**：`integer_marriage` 的整人配对发放（只换回流体婚姻 ⇒ 数字回到 ~1.6–1.8%；只换死因为整数 ⇒ 维持 ~1.8%）。`integer_death` 与 `birth` **无责**。
4. **口径勘误**：ADR-004 文字写"固定时长（默认 t=8000）"，**实现缺省是 t=4000**（`--ticks` 的默认，`--gate` 沿用），**CI 跑的是 4000**。t=8000 口径下差值更大（n=400：13.1%）。ADR 的规模表数字 = t=8000 口径（本轮逐字复现），**口径需确权**。
5. A/B 打磨轮与红因无关（三态 + HEAD 复核，逐字相同）。

## 3. 机制证据

1. **轨迹**（trial seed=1, n=400）：resolved 臂两版本**逐位相同**；coarse 臂人口差 t=8000 从 −33（pre）加深到 −66（post），且后段 married_frac 出现过冲（t=7000：coarse 0.968 vs resolved 0.846）。
2. **信用探针**（排除了两个候选）：`death_credit` 有界循环（≤0.85、无停滞），老年质量在 integer 版下**全整桶**（`whole == total`）⇒ 不是"整人桶不足导致死亡欠发"；`marriage_credit` 有界（≤1.7）。
3. **消融**（`run_trial(coarse_flows=…)`，n=400、t=4000、20 trials）：

   | coarse flows | pop mean | 相对 | R>C |
   |---|---|---:|---:|---|
   | integer death + integer marriage（现状） | −20.40 | 5.10% | 0/20 |
   | **只 integer death** | **−7.15** | **1.79%** | 4/20 |
   | **只 integer marriage** | **−19.80** | **4.95%** | 0/20 |
   | 全流体（pre-fix） | −6.50 | 1.62% | 5/20 |

   ⇒ **台阶 ≈ 全部由 `integer_marriage` 贡献**。领先假说（待修复轮验证）：发放的**选择/摊派规则**（"最大桶优先、整对取人"）改变了被婚配者的年龄结构（相对流体版的按桶占比摊派），使可生育（18–50）人群的婚配节奏偏离 resolved ⇒ 生育闭合放大。**根因未钉死，属修复轮范围。**

## 4. 口径勘误（t=4000 vs t=8000，ADR 文字与实现不一致）

| 口径 | 落地 `5b9dc0b` | 现值（≥ `d739304`） |
|---|---|---|
| **t=4000**（实现缺省，**CI 实际**） | 1.62% / 1.43% / 0.26% — **PASS** | 5.10% / 3.23% / 0.91% — FAIL |
| **t=8000**（ADR 文字"默认"） | 4.56% / 1.04% / 0.66% — **PASS**（= ADR 规模表数字**逐字**） | 13.08% / 7.55% / 4.79% — FAIL |

- ADR-004 的"pop 5% 是当前观察上界（n=400 实测 4.6%）"正是 t=8000 口径——**余量 0.44pp** 的警告当时就写下了。
- 同一份代码，两个口径的误差不同（t=8000 更严）⇒ 门槛必须先**确权口径**（文字与实现取一，或双口径分列）。
- 附：age_l1 趋势规则**长期处于刀刃**（多个种子块在容差 ±0.001 内，落地时 +0.0037），无论口径如何都建议一并复核。

## 5. 决策（**已拍板：A 修因**）

- **A. 修因（已拍板，已实施）**：修 `integer_marriage` 的发放选人规则，把超产拉回 pre-fix 水平以下。实施与验收：[`2026-10-19-integer-marriage-fix.md`](2026-10-19-integer-marriage-fix.md)；ADR-010 修订（收窄）。**结果：门禁 t=4000 PASS（1.23%，改前 5.10%）。**
- **B. 重校准门禁（未采纳）**：承认台阶、按数据调上限/口径（ADR-004 修订）。会把 5–13% 的偏差当基线接受。
- **C. A+B 兼施（未启动）**：残余的既知 ~1.6% 超产仍登记在 ADR-004「需要跟进的」；口径确权（t=4000 vs t=8000 文字不一致）仍待办。

## 7. 教训（登记）

1. **口径必须与数字一起写**：本次曾把 t=8000 与 t=4000 的结果误读为"B 的混沌放大"（见 [`2026-10-18-core-operator-polish.md`](2026-10-18-core-operator-polish.md) §4 勘误）。
2. **验收声明要用门禁口径复现**：`d739304` 提交信息称"cluster_fidelity age_l1/pop 与修复前一致"，实测不成立（5.10% vs 1.62%）——推测当时未按 `--gate` 缺省口径跑。
3. **文档写的默认值必须与代码一致**：ADR-004"默认 t=8000" vs 实现默认 4000；CI 因此长期在跑比 ADR 记录更松的口径。
