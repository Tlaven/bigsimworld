# ADR-011: 分辨率换档默认启用最小驻留（`min_dwell_ticks = 30`）

## 状态
accepted（2026-10-18）

## 背景

Stage 25 引入两项换档纪律（滞回 `theta_down` / 最小驻留 `min_dwell_ticks`），当时**一律缺省 No-Op**，并明确"默认拍板等幽灵换档修复后重测"（见 [`reviews/2026-10-18-resolution-consistency-audit.md`](../reviews/2026-10-18-resolution-consistency-audit.md) §7）——否则 `blocked` 噪声会稀释驻留的效果。ADR-010 修复后重测（`bench.resolution_switch --ticks 600`，"抖动观测者"压力场景、同观测流）：

| 臂 | 有效换档 | blocked | 驻留中位 |
| --- | ---: | ---: | ---: |
| 无驻留/无滞回（noop） | 431 | 0 | 2 |
| **缺省（驻留 30）** | **127** | 0 | **31** |
| 滞回 θ_down=0.4（无驻留） | 236 | 0 | 9 |
| 驻留 60 | 58 | 0 | 60 |

- 无驻留时换档密集（约 13 个簇、每簇中位驻留 **2 tick**）——每次换档 = 一次身份重采样 + 池/残差簿记，**没有语义收益**；
- blocked 已归零 ⇒ 驻留闸的效果现在可干净判读。
- 该场景是**压力场景**（人为抖动观测）；生产注意力轨迹更平滑，但**预算反馈**（未设种子时每 tick 调整 `budget_leaves`）会让预算边缘的簇来回翻转——驻留闸对这类抖动是纯收益。

## 考虑过的方案

- **方案 A（采纳）默认 `min_dwell_ticks = 30`**：只**延迟**换档（升级/降级两向），不放行新的换档、也不永久阻止；30 = `form_interval` 的量级（边界维护节拍），且远小于 `grace_ticks = 180`（bind 冻结）。
- **方案 B 默认 60**：A/B 读数更漂亮，但没有生产依据把最大延迟翻倍；保守取 30。
- **方案 C 同时默认启用滞回（`theta_down=0.4`）**：滞回改变"保持阈值"的**语义**（已 resolved 的簇在 `[θ_down, θ_base)` 保持），其收益依赖注意力分布形态；生产（观察者 / 内生凝视 / 预算反馈 / 显要地板）的注意力轨迹没有实测 ⇒ **保持 opt-in**，等生产观测再拍。
- **方案 D 维持 0（No-Op）**：抖动场景下中位驻留 2 tick 的 churn 无收益；且"噪声源已除"正是本轮重测的前提，继续推迟没有理由。

## 选择

方案 A。要点：

1. `ResolutionManager(min_dwell_ticks=30)`——**缺省启用**；构造参数传 0 可完全关闭（回退路径）。
2. **语义边界**：驻留是节流器，不是策略——它不改变"谁该换档"（注意力/预算/显要/宽限的判定照旧），只限制同一簇两次换档的间隔；**宽限期（bind 冻结）优先，两者独立**。
3. 滞回（`theta_down`）保持缺省关闭（= `theta_base`，无滞回）；启用与否属后续独立决策（需生产注意力轨迹）。
4. 确定性不变（驻留判定无 rng）；快照语义不变（`min_dwell_ticks` 是构造参数，不随档；`_last_switch` 照旧往返）。

## 后果

- **正面**：换档 churn 有上界（同一簇 ≥30 tick 才可能再换）；身份重采样与簿记开销下降；预算边缘的抖动不再造成逐 tick 翻转；故障语义不变。
- **负面 / 边界**：
  - 换档最多延迟 30 tick（两个方向）——注意力真实变化时，响应有界滞后；
  - 生产轨迹会变（换档时机），但权威门槛（收敛 / 保真 gate / 守恒审计）都不以调度器为参量；
  - 若将来需要"更快响应"的场景，参数可下调或按场景注入。
- **回退**：`ResolutionManager(min_dwell_ticks=0)` 即恢复逐 tick 判定。

> **状态更新（2026-10-18，生产样态观测）**：注意力轨迹观测（[`reviews/2026-10-18-attention-trace.md`](../reviews/2026-10-18-attention-trace.md)）显示——衰减 + 内生凝视 + 显要三路下注意力**结构性单向**（每簇一次下穿、上行穿越 = 0）⇒ 滞回**无振荡可抑、只推迟一次性降档**。**滞回维持 opt-in**；若将来要开，需要的是观测 live runner 里 `feedback` 的边际翻转，而不是再测衰减。
