# ADR-003: 跨分辨率直接交互 = transfer（无身份）+ bind（有身份），且建边先扣后加

## 状态

accepted（2026-10-17 起草并同日拍板；范围 = **通道**，交互规则另行决策）

## 背景

第三章把"测度（匿名）/ 窗口（个体）"推广成**分辨率连续谱**，但当前两层之间只有**质量耦合**，没有**信息耦合**：

- 所有跨分辨率流动都必须经全局测度**中转**（`C —overflow_fraction→ 全局测度 —materialize→ 窗口`）：**两跳、匿名、单向**；
- 测度层的速率是**硬编码常数**（`transitions.py` 的 `DEATH_RATE` / `BIRTH_RATE` / `MARRIAGE_RATE`），
  个体在窗口里的事件**不影响**宏观；
- 于是"共演单元"（co-evolution）名不副实——它交付的是**隔离**（族内继承池），不是**共同演化**。

要让 R↔C 直接交互，必须先回答三个绕不开的问题：

1. **粗侧没有 id**：C 是分布（稀疏计数），不是对象。任何"我知道你是谁"的接口都实现不出来。
2. **重复计数**：测度层已按速率算过一次婚配/生育；若窗口再"凭空"建立同类边且不扣减质量，就是**双重记账**。
   这是本层唯一的、比守恒更隐晦的正确性风险——**守恒可以完全成立而仍然重复计数**。
3. **方向不对称**：C 无法"发起"（没有对象），所以 C→R 与 R→C 不能用同一个语法表达。

触发：作者决定为"共演单元 ↔ 单位个体"的直接交互**先建通道、后定规则**。

## 考虑过的方案

### 方案 A：双原子通道 + 先扣后加（采纳）
- **transfer**：无身份的质量移动（可交换、不产生边）。
- **bind = extract + link**：有身份的绑定；**必然且恰好析出 1 个具名个体**（与方向无关）。
- 先扣后加（reserve → commit → rollback）由**通道强制**，规则拿不到旁路。
- 优点：守恒与确定性由**一个**地方保证；方向对称（②③ 是一套实现）；
  "要不要析出"由不重复计数律**唯一确定**，不再是设计口味。
- 缺点：`bind` 引入新的不变量面（配额、宽限期、方向可交换），必须一并定义。

### 方案 B：单一"交互"原语，语义全交给规则（被拒）
- 优点：接口最少，规则最自由。
- **拒绝理由**：守恒、顺序、重复计数这三件事**无法由规则各自正确实现**——
  每条规则都会重新发明一遍账本（这正是 Stage 3/7 的教训：per-cell 账本 → 凭空注水 +1.39e8）。
  通用机制必须收在通道里。

### 方案 C：边际化建边 / 匿名对手方（被拒）
即"给 R 一个概率性的匿名配偶/朋友"，不扣减 coarse 质量。
- 优点：零成本、不碰窗口容量。
- **拒绝理由**：双重罪——① **重复计数**（测度层已算过），
  ② **伪造身份**：产生"半个身份"（有边却无对象），窗口里的关系图与"活的世界"当场失真，
  并连锁破坏 `life_log`、继承指名、家谱。

### 方案 D：id 式寻址（被拒）
即意图直接携带对方 id。
- **拒绝理由**：粗侧**没有 id**。这不是实现难度问题，是**表达不出来**——先按此设计必然推倒重来。

### 方案 E：继续经全局测度中转（保持现状）（被拒）
- 优点：不动任何不变量，零风险。
- **拒绝理由**：两跳、匿名、单向；无法具名、无法反向发起；宏观永远学不到个体事件。
  维持此方案 = 承认"共演"是招牌而非机制。

### 方案 F：为每种规则各写一套专用通道（被拒）
- **拒绝理由**：违反"机制通用、策略可插拔"（[`adr-001`](adr-001-resolution-layer.md) 的立场）；
  且守恒会散落在 N 个地方，审计无法覆盖。

## 选择

**方案 A。** 理由：

1. **守恒与确定性收口在一处**——`bind` 的侧效应（改 coarse 分布、改窗口容量）由通道独占，
   规则只能"提交意图"，拿不到旁路入口。
2. **"要不要析出"由不重复计数律唯一确定**：会产生边的交互必须先把质量从 coarse 侧移出；
   只调制速率/质量的交互不必。这把设计问题降成了定理。
3. **②③ 合并为一套实现**（方向无关，都恰好析出 1 个），工作量减半。

**取舍**：为了可审计，牺牲了"规则自由"——规则不能自定义守恒协议；
`Match` 被迫**声明式**（不能是任意闭包），因为闭包无法静态校验、无法预估配额、无法确定排序。

### 已拍板（2026-10-17，作者）

三条未定点均**采纳本 ADR 的推荐值**；下面保留"当时为什么推荐"（决策型陈述只增不改）。

1. **`marital` 可寻址 = 双人析出**（采纳推荐）。
   - 理由：个体引擎里"已婚"由 `relationships["spouse"]` 决定，**不是独立属性** ⇒ 从**已婚桶**析出一个"单身"人是**语义错误**（今天的物化路径正是如此：`cluster.py` 丢 `_marital`、`generate_character` 默认单身）。
   - 实现：`RECONSTRUCTIBLE` 扩到含 `marital` + `extract(amount=2)`（同桶取 2.0，`link` 成配偶）。
   - **代价**：属 **N2** 改动 ⇒ 实现前必须 teach-back（铁律 9）；通道账本 / 配额形状要扩（一条 `bind` 扣 2 人）；新增一条建边路径 ⇒ 会移动度分布 / ρ / 保真度读数。
   - 备选（未采纳）：宣布 `marital` 为**不可寻址维度**——简单，但等于承认测度层的婚配维度"只写不读"，且物化丢婚配的保真 bug 继续挂着。
2. **配额形态 = 常数**（采纳推荐）：`cap_per_cluster=2`、`cap_per_tick=8` + 窗口 headroom。
   - 理由：可对账、不随规模漂移；`cap_per_tick` 同时是**窗口吞吐的硬上界**（规则变多时需重估）。
   - 备选（未采纳）：随规模 / 注意力缩放——行为随 N 与机器漂移，与"同种子同发展"冲突。
3. **宽限期 = 通道机制**（采纳推荐）：`_grace_ids(tick)` 在 `allocate()` **之前**给出**分辨率冻结集**（不换档、不回收），`grace_ticks=180`。
   - 理由：它是**绑定正确性**的一部分（刚建好的关系不该立刻被粗化掉），且冻结集必须与账本同处一地才可对账。
   - 备选（未采纳）：归**调度策略**——策略要读通道状态 ⇒ 反而耦合。
   - **实现教训**：不得用"抬注意力到 `theta_base`"实现——`allocate` 会据此把该簇**物化**，与意图相反。

> 第 4 条（分辨率层保真门槛）**不属本 ADR**（它是共演单元层的质量标准，不是通道的形态选择）⇒ 已另立 [`adr-004-cluster-fidelity-gate.md`](adr-004-cluster-fidelity-gate.md)。

## 后果

### 正面后果
- R↔C 有了**一跳、双向、可具名**的路径；"共演"具备了成为机制的可能。
- 守恒、确定性、重复计数三个风险**收敛到一个模块**，可被单点审计。
- 顺带清偿三笔既有债：三套边表示统一（`link` 成为唯一入口）、`extract` 改用注入 rng、
  `person → cluster` 反向索引；并顺带获得"物化丢婚配"这一保真 bug 的修复路径（未定点 1）。
- **④ 的质量部分被降级为"开关问题"**：族间财富流动就是一次 `transfer`，
  不再是"跨共演单元社会网络"级别的架构决策。

### 负面后果
- 新增不变量面（配额 / 宽限期 / 方向可交换），若不定义，`bind` 会无界膨胀或不可复现。
- `Match` 被迫声明式，规则表达力受限（换来的是可静态校验）。
- 通道本身**不产生任何语义**——在规则注册之前，它是一条"通电但不做功"的电路，
  容易被误读为已经实现了交互。
- `transfer` 涉及具名个体时受**整数桶步**约束（否则碎片化），因此财富移动有量化残差，必须留池对账。

### 需要跟进的
- 三条**未定点已拍板**（2026-10-17，见 §选择「已拍板」）：`marital` 走**双人析出**、配额取**常数**、宽限期**归通道机制**。
  后两条**已实现**（本期 MVP 值即最终值）；`marital` 属**待实现**——实现前先 teach-back（N2，铁律 9）：
  扩 `RECONSTRUCTIBLE` + `extract(amount=2)` + 通道账本 / 配额形状（一条 `bind` 扣 2 人 ⇒ `delta_mass=-2.0`）。
- **`transfer`（质量侧）移出本期**：它不产生身份，可交换，但有本期未解决的硬问题——
  coarse 侧财富只能按 `count × 桶宽度` 整桶挪动，而具名个体侧是精确浮点 ⇒ 两向转移都产生量化残差，
  残差需要一个"通道池"承接，并需要一条**独立的财富守恒不变量**（形如 `audit_ledger` 的 `pool_residual`）。
  规格留待第二期，本期**不实现、不声明**。
- 交互规则（婚配 / 结友 / 继承）作为**第 9 缝**另立决策；本 ADR 不预设其内容。
- 若将来开启 ④ 的**质量**部分（族间流动），须显式记录：
  `overflow_fraction = 0.0` 之下量到的"富族恒富"（`bench/cluster_inheritance` ≈ 181×）
  是**缺口的产物**而非模型的发现——否则会被误读为结论。
- 本决策推翻了"跨分辨率交互只能经全局测度中转"这一隐含前提；正文已同步
  （[`docs/modules/interaction-channel.md`](../modules/interaction-channel.md)、
  [`docs/cluster-contract.md`](../cluster-contract.md)）。
