# ADR-009: 大众婚配 = 扩展类规则（`MarriageRule(target="measure")`，默认关）

## 状态
accepted（2026-10-18）

## 背景

Stage 21 的校准结论：生产样态下跨分辨率婚配 crossings = **0**——大多数单身在**全局测度**里，而规则只能同"族内单身"成婚（coarse 族几乎不含 18–59 未婚桶）。通道侧随后补了全局测度寻址（ADR-008 / N2-8），并把"规则侧是否把大众纳入候选"显式留为**独立决策**。

2026-10-18 测量轮（[`reviews/2026-10-18-mass-marriage-measurement.md`](../reviews/2026-10-18-mass-marriage-measurement.md)）用 bench 脚手架探针给出双解读数（N=1200/C=240/t=2000，4 seeds，生产样态）：

- 通量随 rate 近似线性：0.05× / 0.10× / 0.25× / 0.50× / 1.00× ⇒ crossings **2.5 / 5.5 / 12.5 / 24.5 / 51.2**；1× 时合并已婚比例 **+6.4±1.0pp**（Δ vs null）；配额从未触顶，headroom 丢弃 ≤4/run；
- 守恒：逐次 `worst |Δpop| = 0`、`|ΔW| = 1.5e-8`（63 crossings / 3000 tick）；
- **关键读数**：off − ref 的 −1.13pp 缺口基本由 **headroom 效应**（null − off = +1.00pp）解释（null − ref = −0.14pp、SE ≈ 1.6pp）；通量从最小档起就是**加法** ⇒ **不存在可分辨的"补差"窗口**。

## 考虑过的方案

- **方案 A（采纳 = 扩展类规则，默认关）**：`MarriageRule` 增加 `target ∈ {"cluster","measure"}`；`measure` 模式 = 窗口单身 × 全局测度匿名单身（R→M）；`SIM_CHANNEL_MARRIAGE` 扩展取值（`0` 默认关 / `1` 簇 / `mass` 大众），**单值互斥**；开启语义沿用 ADR-007：**新增婚配通量、不属于参照模型的近似**（收敛/保真门槛一律只在默认关闭下跑）。
- **方案 B（作为"保真修正"：用最小 rate 补 −1.1pp 缺口）** —— **被拒**：测量显示该缺口由 headroom 效应解释、且 ref 对比噪声为 ±1.5pp 级；通量从最小档起即为加法。若强行"补差"，得到的参数落在噪声里 = **伪精确**（"调出来"的数字不承载语义）。
- **方案 C（`cluster` + `measure` 并存：`target="both"` 或同时注册两条规则）** —— **推迟（本轮不做）**：同一 tick 两条意图会让**同一人双婚**（通道不在 reserve 时复检发起者的婚配态；去重键含 `scope`，挡不住两条不同 `scope` 的意图）。要做必须配"一人一意图"守卫或合并抽样，属另一设计；当前无需求驱动。
- **方案 D（维持现状：能力只留 bench 脚手架）** —— **被拒**：与 A 相比没有额外安全性收益（A 的默认关已保证生产读数不变），只是把已验证的能力留在脚手架里、失去测试与规格的护栏。

## 选择

方案 A。要点：

1. **语义定位 = 扩展**（不是近似、不是保真修正）。任何"开启后与个体引擎收敛"的主张都不成立。
2. **默认关**：`SIM_CHANNEL_MARRIAGE` 缺省 `0` ⇒ 不注册 ⇒ 生产权威数字不变。
3. 开关**单值互斥**：`1` = 簇规则（现状）；`mass` = 大众规则（`target="measure"`）——结构上排除"两条规则同时注册"的双婚路径。
4. 规格 = N2-7 的「候选侧」增补（含危险实现清单新行）；验收 = 新测试 + **复跑测量与台账一致**（同一 rng 纪律、同一世界构造 ⇒ 数字须可对齐）。
5. 配额/宽限语义自动继承 N2-8：豁免 `cap_per_cluster`；`cap_per_tick` 与窗口 headroom 仍是硬上界。

## 后果

- **正面**：能力进入生产代码（有规格、有清单、有测试、可审计）；生产默认读数不变；"真实共演化"演示有了可开的大众档（1× 时 2000 tick 约 51 桩跨界婚配）。
- **负面 / 边界**：开启后显著抬高合并已婚比例（1× +6.4pp）；测量为单规模单时长（N=1200/C=240/t=2000）——生产规模读数会更大、定性不变；`both` 未做（一人一意图守卫未设计）；通量上限受 `cap_per_tick = 8/tick` 与窗口 headroom 约束（当前不触顶，高 rate 下会先触）。
- **跟进**：若要 `both` / 生产速率定标 / 跨规模扫描，另行测量与 ADR。

> **状态更新（2026-10-18，ADR-012）**：方案 C 的推迟条件（"一人一意图"守卫）已解除——通道在 `bind` 执行前复检发起者婚配态（`dropped:initiator_married`），`SIM_CHANNEL_MARRIAGE` 新增 `both`（簇 + 大众并存）。

> **状态更新（2026-10-18，跨规模扫描）**：跟进项"生产速率定标 / 跨规模扫描"已测（[`reviews/2026-10-18-marriage-scale-sweep.md`](../reviews/2026-10-18-marriage-scale-sweep.md)，N=1200/2400/4800，`scope=both`）——通量密度人均稳定（~9–12 / 千人口 / 2000 tick @0.5×–1.0×）⇒ **速率无需按 N 重标**；Δmarried vs null ≤ +0.02 且有界；族侧先饱和（1.0× 时丢弃随 N 超线性）。**建议：若开生产用 rate ≤ 0.5×；默认关不变**。
