# ADR-002: 显要（notability）= 财富高位分位，且不逐出 / 不粗化

## 状态

accepted（2026-10-16，实现在 `app/core/measure/cluster.py`；规范 [`docs/engineering-spec.md`](../engineering-spec.md) §9）

## 背景

"对世界影响极大"的个体若被并入**粗化**的共演单元，会失去特殊性；同时微观窗口需要让人感到"**确实存在大量独立单位**"。需要一个**可审计**的"显要"判据 + 明确的**保护策略**。（此前只有显式 pin 能让个体保持高分辨率，没有任何"自身世界影响"的判据。）

## 考虑过的方案

### 方案 A：财富高位分位（采纳）
- 优点：财富是本模型**唯一可守恒转移、且真实驱动宏观**的量（死亡注入 `wealth×0.1` 遗产；gini 是头条指标）；阈值由**全局测度确定性推出**，可解释（"此人财富高于全人口 top q"）、可复现。
- 缺点：财富是 1000 宽的分桶，**边界并列会过包含**（名义 top 1%、实际约 1.9%）。

### 方案 B：关系枢纽（度）（被拒）
- 优点：社会影响力直观。
- 缺点：宏观流对网络度不敏感；定义依赖图结构、成本高。
- **拒绝理由**：与"世界影响"（宏观可测量）相关度弱，且难审计。

### 方案 C：复合评分（被拒）
- **拒绝理由**：不可解释、难审计，违背"守恒可审计优先"。

### 方案 D：跨共演单元社会网络（T3）（被拒）
- **拒绝理由**：微观窗口的目的 = **显要者 + 感知个体**，不是跨簇交互；收益低、复杂度高。

## 选择

方案 A。判据**可插拔**（替换 `ResolutionManager.notability`）；分位 `SIM_NOTABLE_FRACTION`（默认 `0.01`，`off` 关闭）；`ResolutionManager` 层**默认关闭**，生产由 runner 开启。

**保护策略**：显要者 ① **绝不逐出**（计入 `protected_ids`）；② 其共演单元**无视预算强制保持 resolved**（注意力地板 + 强制 target=1）——绝不被粗化。

## 后果

### 正面后果
- 关键个体不再被粗化而丢失特殊性；`notables` 含**未入组的浮层者**，观测可见。
- 判据确定、可审计（`resolution_summary.notability` 给出 `metric/fraction/threshold/notable_count`）。

### 负面后果
- 分桶并列导致过包含（可接受：方向是**多保护**，不破坏守恒）。
- 显要者所在共演单元永久占用预算（显要稀有，占用有界）。

### 需要跟进的
- 若需严格分位：把判据改为严格 `>` 或更细分桶（均不动核心）。
- 若将来要"关系枢纽 / 复合"判据：仅替换 `notability` 对象（已留接口）。
