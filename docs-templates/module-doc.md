### 危险实现清单(3 种"看起来对、语义却错"的写法)

> 先写这栏,再写不变量——不变量的用途就是挡它们。**每条必须被某条不变量或某条验收挡住**;挡不住 = 规格还没想清,不是"实现的人会注意"。**写法**:「由谁挡住」列要有内容、不能是占位符(`—` / `待补` / `TBD`)——列数不限,机器按**表头含"挡住"的那一列**粗检填没填;**推荐直接写证据**("挡住——负例:…" / "挡住——fixture 计数(…)"),而不是只挂一个编号;写法是否真挡得住仍归复核。**反向也查一下:每条不变量至少挡掉清单里的一种错法**——一条什么都不挡的不变量等于没写。

### 失败语义(逐条,别写"合理处理错误")

| 失败路径 | 可重试? | 幂等? | 对外表现 | 观测(日志 / 指标) |
|---|---|---|---|---|
| 超时 | | | | |
| 部分成功 | | | | |
| 冲突 / 并发写 | | | | |
| 校验失败 / 越权 | | | | |

> 判据同术语表:写不出"调用方看到什么"的失败处理 = 还没定义。外部依赖的每次调用都要能在这张表里找到归属。**检查器会粗检本节存在**（指针形除外）。
> **每行必须配一条断言该承诺的测试**——断言的是**调用方 / 玩家能观察到的东西**（原档还在 / 资源没减少 / 状态停在哪儿），不只是"返回了错误码"。**没有断言的承诺，一次重构就会退化**。
> **上面四行只是示例,按领域增删**——纯计算模块把"超时 / 并发"换成"精度溢出 / 输入缺件 / 依赖缺失"即可。目标不是填满,是**每条真实失败路径都有归属**。
