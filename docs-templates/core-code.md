# Core Code — L4 核心代码层(可选)

> **使用方式:** 仅在项目有"牵一发动全身"、且**被多处共用**的核心单元时才创建本文件。
> 默认不要——简单项目三层(L1/L2/L3)够用;**建层判据只有一条:加载闭包 ≥ 2**(≥2 个工作场景必须把它当前置读)。只有入度 1 的 N2,留 L3 就够;跨模块契约没建 L4 时住 L2 的架构级约束。
> 三段式:[是什么] / [为什么] / [不变量]
>
> **本层是 N2 的第二个落点(不是唯一落点):** 通用 CRUD / 胶水不必进这里;真正新、AI 训练数据里没有对应模式、**且命中本层收录标准**的核心逻辑,**必须**在这里写到"可实现"——否则 AI 只能猜(见下方「novelty 分档」)。模块内的 N2 仍留在它自己的 L3。
>
> **层的划分按"加载图",不按抽象粒度:** 一层存在的理由,是"有一批工作场景必须同时加载同一批东西"。所以判据是**加载闭包 ≥ 2**(≥2 个工作场景把它当前置读);**入度只有 1 的 N2 不进本层**——它留在该模块 L3。
>
> **N2 落点(先看这条):** 属**模块内**且**不**跨模块 / 不属骨架 / 不高扇入的 N2 → 记该模块 `docs/modules/<name>.md` 的 N2 栏;**命中跨模块 / 架构骨架 / 高扇入任一(判据:被 ≥2 个工作场景当前置读) → 记到公共处**:建了本层就进本文件,没建本层就进 L2 的 `[不变量]` 架构级约束。
> **只许一处成文**(高扇入的逻辑若只放模块 L3,别的模块按"分层加载"根本读不到,会各自重复实现或改坏它);该模块 L3 只留一行指针(E1),不要两处各写一份。

## 收录标准(先看这条)

> **N2 落点:** 见文件顶部「N2 落点(先看这条)」——纯模块内的 N2 留 L3;命中跨模块 / 骨架 / 高扇入(判据同顶部)则进本文件,该模块 L3 只留一行指针。**未建 L4 时,跨模块契约的合法家是 L2 的 `[不变量]` 架构级约束**(模块边界规则 / 跨模块通信方式)——写在那里 + L3 留一行指针,同样成立;**别把"N2 无处可写"当成必须建层的理由。**

### 收录标准一:哪些**单元**进 L4

**单位是"单元",不是"函数"。** 四类单元都收,卡片形状见下节:

| 单元类 | 判据 |
|---|---|
| **函数** | 满足下面五条收录标准至少一条 |
| **表示**(数据模型 / 编码 / 身份语义) | 被 ≥2 个工作场景当前置读,**且**改了等于重写 |
| **协议**(唯一通道 / 通信方式) | 定义了"内容只能怎么进 / 怎么出";绕开它 = 静默坏 |
| **公共后置条件** | 任一单元改完都必须维持的性质(如"写(读(x)) 逐字相同") |

### 收录标准二:五条标准(函数类,满足至少一条)

> 以下五条是**单元筛选**;仍须先过建层判据(加载闭包 ≥ 2)——过不了的单元留在它自己的 L3。

- **高扇入公共依赖**:很多模块调用它(改签名 / 语义 = 全项目改)
- **架构骨架**:定义了项目的主要数据模型或抽象(改了等于重写)
  - **收窄:** 若**整个项目的核心就是该骨架**(核心 = 一套表示的项目),它属 L3 / L2 的**正文**,**不进本层**——本层只收骨架里**横切**的那部分(被别的模块也当前置读的少数几条)。
- **不变量守护者**:隐含"调用前必须 X / 返回后保证 Y",违反就出隐蔽 bug
- **执行流入口**:故事从这里开始(主循环、事件分发、顶层 API)
- **AI 未见的领域核心**:非通用算法 / 领域特有推理(训练数据里没有现成模式)——且须**跨模块 / 架构骨架 / 高扇入**(模块内的这类逻辑记 L3)

**条目数(定性,不设数字):** 核心单元应**明显少于**模块内的普通函数;若条目数 **≈ 模块数**,说明你把模块拆成了卡片——那是标准放松的信号,不是"这个项目核心很大"。
判断尺度:**"改了会出大事"才进,不是"用了很多次"就进。**

**建层本身是一次结构决策** → 记一条 ADR;被拒方案写清:把这批单元留在 L3 与 L2 的公共节里,代价是什么(通常是"别的模块按分层加载读不到,会各自重造")。

## novelty 分档(决定要写多细)

| 档 | 含义 | 这里要写到什么程度 |
|---|---|---|
| N0 通用模式 | AI 见过(排序、重试、CRUD…) | 职责 + 不变量足够,细节交给代码 |
| N1 项目特有 | 组合方式特殊,但积木是通用的 | + 主流程叙述 + 关键决策(为什么) |
| **N2 AI 未见** | **领域特有 / 创新逻辑,训练数据无对应** | **+ 步骤级说明(必填) + 危险实现清单 + 精确例子 + 可跑验收** |

> N2 是核心中的核心:你不给步骤级说明,AI 一定会用"看起来像"的通用方案猜,且错在深处。
> **"步骤级说明"不是越俎代庖替 AI 写代码,是把逻辑讲到它接得住。**
> 判据(定边界):**删掉这句会让实现产生歧义吗?会 → 留;只是让实现更快 → 删。**

<!--

### 例一(函数卡) `matchSlot` — `slot_matcher.py:42` · novelty=N2
- **职责**:为一条订单选出一个满足约束的装配位
- **前置不变量**:订单 `status == "PENDING"`;装配位未被占用
- **后置不变量**:返回的 slot 满足 `slot.used + order.weight <= slot.capacity`;无解返回 None
- **谁必须读它**:凡改"订单分配 / 容量校验"的模块,动手前加载它
- **为什么它是核心**:容量充裕的槽要留住——挑最小可容纳者,大件才总有位置

**步骤级说明**
1) 过滤出 `capacity - used >= order.weight` 的候选槽
2) 候选按 `capacity - used` 升序,取第一个
3) 无候选 → 返回 None
   不变量:任何时刻 `slot.used + order.weight <= slot.capacity`

**精确例子**
| 输入 | 输出 |
|---|---|
| order{w:3}, slots[{cap:5,used:0},{cap:10,used:0}] | 第一个槽 |
| order{w:9}, slots[{cap:5,used:0}] | None |

**验收**
- 命令:`pytest tests/test_slot_matcher.py` · 预期:通过
- property:对随机 order/slots,若返回非 None,则 `slot.used + order.weight <= slot.capacity` 恒成立

### 例二(表示卡) `<资源 ID 的规范形>` — (表示) · novelty=N2
- **它是什么**:资源 ID 的规范写法(前缀 + 定长段那类"一种写法")
- **定义域 / 规范形**:取值域是什么;规范形**唯一**吗——不唯一就先写清归一的办法(去前导零 / 去尾 / 大小写)
- **相等判据**:按规范形逐字比(**不是**按解析后的数值比)
- **公共后置条件**:任何写入者都要保证"读回来的值能写成同一个规范形"(写(读(x)) 逐字相同)
- **谁必须读它**:凡建 ID / 存 ID / 比对 ID 的模块——改标识语义前必读
